# 预演负载与代理验证

```sh
npm run build
npm run load:smoke
LOAD_CLIENTS=100 npm run load:smoke
```

脚本启动真实`NODE_ENV=production`进程，通过WebSocket并发连接，每个客户端携带不同的`X-Forwarded-For`，服务端配置`TRUST_PROXY_HOPS=1`模拟仓库提供的单层Caddy。每个客户端创建一个观战房间并同步状态，最终输出成功数、P50、P95和最大端到端延迟。

默认40客户端，允许1至200；P95超过10秒判定冒烟失败。脚本显式使用静态题目和占位模型Key，不进入游戏、不调用知乎或模型，不产生外部费用。

2026-09-11本地基线：40/40成功，P50约208ms、P95约222ms、最大约223ms。该数据只用于发现明显回归，不是生产SLA。

覆盖本地production mode的Next/Socket/SQLite启动、Origin与WebSocket、模拟单层可信代理IP、并发房间创建、会话保存、状态同步和优雅关闭。

未覆盖真实Caddy/CDN链路、校园网共享IP误伤、完整玩家对局、AI并发、长连接持续时间，以及CPU、内存、文件描述符、磁盘和带宽容量。正式预演应在目标服务器逐级增加负载并监控资源，在错误率或资源达到阈值时停止。

## 分阶段压测记录

使用 `npm run load:staged` 先执行 10、40 客户端阶段，再保持 30 分钟。可用 `LOAD_DURATION_MS` 缩短本地演练。它会输出阶段边界、样本时间、主机内存和 CPU 数量；CPU、内存、文件描述符、磁盘、SQLite 写入、备份耗时和网络指标必须由目标主机监控系统同时采集。

正式报告必须逐阶段记录环境（应用提交、Node、容器/宿主机、CPU/内存/磁盘、代理、客户端数量）、Socket连接成功率、命令回执延迟、状态广播延迟、AI等待时间、SQLite写入耗时、内存增长、活动房间数、断线重连成功率、题目/模型供应商错误率，以及断线、重连、刷新、会话接管和备份并发结果。至少覆盖10个和40个完整玩家房间、观战/玩家/AI混合、多个房间同时进入AI阶段，并逐步增加资源压力。

仓库现有 `load:smoke` 与该脚本默认使用静态题目和占位模型，不能证明完整玩家对局、真实AI并发、30分钟长连接或公网容量；本地 P95 不能单独作为结论。磁盘写满、宿主断电、异地恢复和正式SLA仍需目标服务器单独验收。
