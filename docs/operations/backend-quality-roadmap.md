# 后端质量与优化路线

当前后端基线是单实例 Node.js + Next.js + Socket.IO + SQLite。核心状态机、会话恢复、SQLite CAS/WAL 恢复、备份校验、管理员审计和临时 Compose 验收均已有代码或自动验证；这些证据不能替代正式服务器验收。

## 已完成的基础设施

- 临时 Compose 集成：健康检查、Socket/Origin、双会话房间同步、备份命令、重启和清理。
- 备份恢复：元数据、SHA-256、完整性校验、安全恢复到新文件、损坏文件拒绝和 WAL 恢复演练。
- 管理员边界：原因字段、版本确认、Token 指纹审计、限流，以及公共 Caddy 入口阻断管理员路径。
- 内容安全：确定性过滤、规则版本、稳定错误码、不可逆摘要和上下文类型。
- 题目核验：可选持久化缓存、TTL、来源/版本、失败分类、同进程去重、文件锁和额度耗尽告警。
- 分阶段负载工具：10/40 客户端阶段和长连接保持；当前默认仍是静态题目/占位模型冒烟。

## 当前应继续做的后端工作

1. 将 Socket、命令回执、广播、AI、SQLite、备份、题目核验和资源指标接入稳定的集中观测与告警。
2. 在单实例约束内继续强化题目缓存的退避、锁超时和运维状态报告。
3. 在目标服务器完成真实持久卷、备份保留、恢复、磁盘和代理链路演练。
4. 使用真实环境逐级执行 10 房间、40 房间、混合玩家/观战/AI、30 分钟长连接和资源压力测试。

## 等前端基础流程完成后

- 浏览器真实弱网 E2E：刷新、断线、重连、会话接管和重复提交。
- 多浏览器完整多人长局和移动端后台挂起/恢复。
- 前后端状态版本、阶段令牌、Outbox 和广播频率联调。
- UI 对 AI 超时、题目失败、管理员错误和恢复结果的展示。

## 不应提前宣称的结论

本地 production mode、静态题目、占位模型、Docker 构建和 P95 冒烟不能证明公网容量、生产 SLA、长期供应商稳定性、完整审核能力、异地恢复或正式运维就绪。多实例、分布式调度和云平台绑定也不属于当前 P0 范围。
