# 浏览器命令确认与重试

游戏写动作使用`commandId + matchId + phaseToken + 原始业务字段`。服务端持久化同一参与者的命令指纹和回执；相同ID/相同载荷返回原回执，相同ID/不同载荷拒绝。

浏览器`CommandOutbox`同一时间只保存一个写命令：

1. 发出前写入标签页`sessionStorage`。
2. 5秒未收到回执，使用完全相同载荷自动重发。
3. 最多自动发送3次；之后保留待确认项并提示状态未知，不允许新写命令覆盖。
4. 断线暂停计时；会话恢复成功后重置自动次数并重发原命令。
5. 刷新页面从`sessionStorage`恢复，会话恢复后继续确认。
6. 收到成功或确定失败回执后清除；迟到的重复回执不重复通知。
7. 会话过期、被接管或主动离开时清除Outbox。

若原命令从未到达且阶段已经推进，重发会得到阶段错误并清除；若服务端已处理但回执丢失，重发会返回持久化原回执。无需新增`command-status`事件。

Outbox属于网络确认机制，不改变游戏规则，也不承诺浏览器关闭标签页后恢复。清除站点数据会丢失未确认项。服务端的一轮一答、一人一票等规则仍是最终防线。创建/加入房间使用独立`requestId`幂等，不进入游戏命令Outbox。
