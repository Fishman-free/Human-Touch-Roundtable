# 数据与隐私说明（工程基线）

## 保存的数据

- 游戏房间保存随机participantId和匿名座位，不保存知乎账号资料。
- 会话Token的SHA-256摘要、创建/到期/最近活动/撤销时间；不保存Token明文。
- 题目来源元数据、角色、三轮回答、辩论、投票、胜负和公开行为日志。
- AI调用的供应商、模型、动作、状态、延迟和Token数量；不记录完整Prompt、模型正文或隐藏推理。

默认终局房间保留24小时，会话保留48小时；运行中房间为保证恢复持续保存。SQLite备份可能保留更久，由部署方制定周期并限制访问。

## 外部传输

可选知乎登录会在后端交换OAuth Token并请求当前用户基础信息。只提取hash_id和昵称，不保留手机号、邮箱、头像或其他资料，取完身份即丢弃Token。服务端内存保存哈希化账号标识、昵称和登录会话到期时间；昵称仅返回本人浏览器，不发送给对手或模型。账号哈希仍属于可关联标识，不应当作彻底匿名的数据。

公共匹配在内存关联账号与房间，以防重复占座。退出清除当前登录会话和未成桌的排队；已成桌关联保留用于恢复，完成对局后的查询、保留期到期或进程重启会清除。登录会话最长24小时；匹配关联最多保留至最近访问后48小时。退出知乎登录不会自动撤销独立房间Token。详见[知乎登录与公共匹配](../operations/zhihu-login-matchmaking.md)。

AI行动会把题目、已公开回答/辩论、匿名座位和服务端角色表发送给配置的模型供应商。不会发送会话Token、participantId、IP或知乎Access Secret。玩家输入在发送模型前经过基础联系方式、凭据和提示注入过滤，但该过滤不是完整匿名化或内容审核。

知乎题目接口接收搜索词和调用方Access Secret；登录接口接收OAuth所需授权码及凭据。两类接口都不接收玩家回答或游戏身份。

## 删除

管理员可按roomId删除在线房间，相关会话由SQLite外键级联删除。已经生成的独立备份不会同步删除，必须按备份保留策略到期删除或人工清理。账号与公共匹配只有临时内存关联，没有持久化历史账号索引；处理历史删除请求时仍由用户提供房间号并完成运营侧验证。

## 上线前事项

- 将本工程基线转化为面向用户的隐私声明和AI处理告知。
- 明确模型供应商的数据使用、留存和跨境条款。
- 确定备份保留、访问审计和删除时限。
- 明确未成年人、举报、内容审核与安全事件流程。
- 启用知乎OAuth前确认授权告知、临时身份关联和用户权利流程，并完成真实登录验收。
